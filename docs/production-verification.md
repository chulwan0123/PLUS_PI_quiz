## 알려진 보완 지점

- 관리자 문제 입력은 DB의 1~3줄 제한을 미리 검증하지 않습니다. 긴 줄은 nowrap 때문에 넘칠 수 있습니다.
- 활성 문제 삭제는 최소 2개를 확인하지만 비활성화 저장에는 같은 제한이 없습니다. 2개 미만이면 기본 문제 fallback이 발생할 수 있습니다.
- 힌트 이미지를 문제 저장 전에 업로드해 취소·교체·연결 해제 후 미사용 Storage 파일이 남을 수 있습니다. 이번에는 이미지 연결을 해제했으며 Storage 파일 자체는 삭제하지 않았습니다.
- Supabase 조회 실패가 운영자에게 표시되지 않아 기본 문제 fallback 여부를 구별하기 어렵습니다.
- `/suri-review`는 검수용이지만 운영에서도 접근할 수 있습니다.
- 초기 데이터 INSERT를 SQL로 직접 반복 실행하면 무작위 UUID와 고유 문구 제약 부재 때문에 중복 문제가 생길 수 있습니다.
